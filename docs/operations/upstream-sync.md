# 个人版本的上游同步

此工作流由 GitHub 管理候选，Codex Cloud 通过订阅执行修改，GitHub 执行独立验证。本机无需构建。正式合并、安装和发布均由维护者决定。

新版执行路径使用官方 Work Cloud 定时任务直接执行代码，通过 GitHub 连接器回写候选，共享 ChatGPT/Codex 订阅额度。仓库变量 `UPSTREAM_SYNC_EXECUTOR=work-cloud` 让控制器只发布交接标记，不调用旧修改入口；独立云端定时任务遵循默认分支固定版本的 `.github/upstream/worker.md`，定期消费候选。先完成云端执行、回写及独立验证金丝雀，再开启正式调度。

`codex-cloud` 保留旧评论兼容路径。接入实测发现已发布的新版环境仍可能被旧入口报为缺少环境；参见 [OpenAI 问题 #20093](https://github.com/openai/codex/issues/20093)。不能把自动审查成功当成修改任务启动成功，也不能导出订阅登录缓存绕过此问题。

## 首次接入

1. 将个人功能及同步代码放入 `codex/personal-main`。将控制工作流、脚本和 `.github/upstream/` 同步到默认分支；无需改变默认分支的产品代码。定时任务只从默认分支运行。
2. 在 Codex 的 GitHub 集成设置连接 `glyahh/t3code`，配置供 GitHub 任务使用的云端环境，安装仓库规定的 Node、pnpm、Vite+。允许获取 GitHub 官方代码及安装依赖，测试状态使用独立 `.t3`，不提供正式数据库或真实安装目录。
3. 创建归属已绑定 Codex 的 `glyahh` 账号的细粒度 GitHub 令牌，仅授权本仓库 Contents 和 Pull requests 读写，保存为 Actions secret `UPSTREAM_SYNC_TOKEN`。令牌只供默认分支控制器使用。不要上传 Codex `auth.json`。令牌过期需替换；不要在聊天或日志中粘贴令牌。
4. 保持仓库变量 `UPSTREAM_SYNC_ENABLED` 缺失或为 `false`。手动运行 **Upstream Sync**，选择 `canary`。控制器使用当前最新正式版本创建接入草稿，发送任务评论；确认 Codex 有响应、实际启动云端任务、修改推回分支，并出现独立验证报告。接入候选故意不能通过正式合并门禁。
5. 关闭接入草稿。接入测试未完整通过前，不启用定时。成功后设置变量 `UPSTREAM_SYNC_ENABLED=true`，每小时第 17 分钟补查版本。GitHub 可能延迟定时任务，公开仓库长期不活动也可能停用计划；可用手动 `scan` 补查。

## 验证与证据

**Upstream Controller Checks** 在云端运行控制器核心回归测试。**Upstream Candidate Validation** 对实际候选提交运行受影响检查和桌面构建，将报告和日志上传为 Actions artifacts，保留 90 天。它从基线加载控制器与策略，以只读权限运行候选；没有同步令牌或订阅凭据。不得向该验证工作流增加写权限或账号密钥。

实际客户端、跨平台、真实 SDK、性能、故障及人工验收不是构建检查的别名。未接入这些执行环境时，报告逐项标记受阻，门禁失败；不能宣布完整验收。

由维护者在受保护基线的 `policy.verification` 配置独立验收命令，每项包含 `name`、`command`、`args` 和覆盖的 `categories`，只配置实际覆盖对应验收场景的命令。命令在隔离候选目录运行，退出码为零才能通过。不得用始终返回成功的命令、候选自己编写的结论或降低样本指标代替证据。每类至少有一套实际执行器，尚缺的类别保持受阻；多套覆盖同一类别时全部通过才通过。人工 UAT 应由云端验收执行器等待维护者对当前提交的反馈后再结束。验收执行器需将原始样本、脱敏日志、截图与录屏写入 `EVIDENCE_DIRECTORY`，由工作流上传；需要长期保留时下载或复制到维护者的证据存储。

流式验收的负载、p95、故障和 A/B 数值在策略中固定。真实提供方使用低成本模型、少量约定样本，其余使用 Replay；不可上传生产账号到普通候选作业。凭据相关执行器必须另外配置隔离云端环境。当前默认 `verification` 为空，因此正式候选会保持受阻，直到实际验收执行器接入。

核心回归测试长期保留，一次性压力和故障测试代码在验收收尾清理，失败记录保留。用户已允许此工作流使用云端标准浏览器和桌面自动化替代内置面板。

## 决策与恢复

同步候选一次只开一个。第二轮自动修复仍失败后停止，手动 `retry` 也不能突破两轮限制。超过等待窗口只提示，不重复投递任务。关闭未合并候选表示暂缓相同官方提交、个人基线和策略组合；后续累计版本继续提示并重新评估此前拒绝原因。

所有结论绑定个人、候选及策略哈希。个人基线变化后旧候选会在下次检查关闭并重建；在合并前必须确认个人分支未变化。为 `codex/personal-main` 配置分支保护，要求候选验证通过和维护者审阅，并限制只能通过 merge commit 合并同步候选，保留官方历史；不要 squash 或 rebase 同步 PR。不要绕过失败门禁或以构建成功替代验收。

回滚通过独立 PR 执行。创建 `upstream-rolled-back` 标签，并标记原同步 PR；后续即使官方提交已在祖先中仍会根据实际树重新评估。未登记的回滚不能仅凭 Git 历史检测，因此必须完成标记。

暂停时将 `UPSTREAM_SYNC_ENABLED=false`；不会停止已经开始的 Codex 任务，需在 Codex 云端显式停止。令牌、额度、云端回写或环境缺失时保持受阻，不退回本机构建或 API 计费。
